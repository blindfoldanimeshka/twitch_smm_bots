1. Общие сведения о проекте
1.1 Назначение системы
Разработка программного комплекса (далее — Система) для автоматизации взаимодействия с чатом Twitch-стримов через использование локальных нейросетевых агентов («боты»). Цель — обеспечить реалистичную имитацию активности сообщества, помощь в онбординге новых зрителей и поддержку стримеров при старте трансляций.

1.2 Целевая аудитория
Twitch-стримеры (начинающие и начинающие)
Команды по маркетингу (SMM-специалисты)

3. Функциональные требования
3.1 Панель управления (Frontend)
F-REQ-01: Статус системы
Отображение общего статуса ботов (Online/Offline)
Общая статистика по сообщениям в минуту/часе
F-REQ-02: Управление ботами
Создание нового бота (название, ID, токен Twitch API)
Настройка персонажа (системный промпт, стиль общения)
Включение/выключение ботов через UI
F-REQ-03: Мониторинг активности
Лог сообщений бота в реальном времени
График активности по времени
F-REQ-04: Настройки нейросети
Выбор модели (например, llama3, mistral)
Настройка контекста чата
Настройка лимита генерации (tokens/min)
3.2 Backend API Server
B-REQ-01: Управление потоками
API для запуска бота по ID
API для остановки/паузы
API для сброса состояния
B-REQ-02: Интеграция с Ollama
HTTP/JSON REST Client к ollama serve
Поддержка Stream Response (опционально)
Кэширование ответов в Redis
B-REQ-03: Лимиты и ограничения
Глобальный лимит на количество сообщений за минуту
Локальный лимит на одного бота (например, ≤10 msg/min)
Защита от банов через ротацию прокси
3.3 Бот-агенты (Go Microservices)
A-REQ-01: Подключение к Twitch API
Получение токена через OAuth2
Чтение сообщений из чата стримера
Отправка сообщений в чат
A-REQ-02: Контекст диалога
Хранение последних N сообщений стримера (окно контекста = 10–15 msg)
Формирование промпта для LLM с учетом предысторьи
A-REQ-03: Лимитирование частоты
Таймеры в Go на уровне бота
Проверка перед отправкой: if last_send + delay < now → skip
A-REQ-04: Поведение персонажей
Система промптов для каждого бота:
Бот "Джон" (веселый)
Бот "Анна" (умный)
Бот "Боб" (фанат)
И т.д.
4. Нефункциональные требования
4.1 Производительность
Задержка от запроса пользователя до ответа бота: ≤2 сек
Обработка одного сообщения нейросетью: ≤3 сек
Конвертация LLM в текст: <5 sec при использовании локальной модели
4.2 Безопасность
OAuth2 токены должны быть зашифрованы (AES-256)
Все внешние запросы через прокси-сервисы
Логи действий ботов с меткой времени
4.3 Масштабируемость
Поддержка до 10 активных ботов на одной машине
Возможность горизонтального масштабирования (добавление Node'ов)
5. База данных (SQL Schema)
-- Таблица Боты
CREATE TABLE bots (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255),
    twitch_id BIGINT,
    oauth_token TEXT NOT NULL,
    proxy_url VARCHAR(500),
    system_prompt TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status ENUM('active', 'paused', 'stopped'),
    rate_limit_min INT DEFAULT 10
);

-- Таблица Логи сообщений
CREATE TABLE chat_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    bot_id INT REFERENCES bots(id),
    streamer_name VARCHAR(255),
    message_content TEXT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_from_bot BOOLEAN
);

-- Таблица Контекст-сессии
CREATE TABLE context_sessions (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    bot_id INT REFERENCES bots(id),
    session_data JSON NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

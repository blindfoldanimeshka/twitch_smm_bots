# Twitch SMM Bot - Product Requirements Document (PRD)

## Обзор проекта

Twitch SMM Bot - это система управления множественными Twitch ботами для автоматической отправки сообщений в чаты стримеров. Бот использует LLM (локальный ИИ) для генерации сообщений с различными личностями, поддерживает ротацию между каналами, аудио-транскрибацию стримов для получения контекста.

---

## Функции проекта

### 1. Bot Management (Управление ботами)

#### 1.1 Создание бота (CreateBot)
- **Как работает**: Принимает POST запрос с данными бота (id, twitch_login, password, name, personality, delays, rate_limit)
- **Зачем нужен**: Создание нового бота в системе с настройami личности и интервалов отправки
- **Валидация**: Проверка обязательных полей, уникальность ID
- **Что добавить**:
  - Валидация Twitch аккаунта при создании
  - Проверка валидности OAuth токена
  - Лимиты на количество ботов

#### 1.2 Запуск бота (StartBot)
- **Как работает**: POST /bots/{id}/start - подключает IRC клиент к Twitch каналу
- **Зачем нужен**: Запуск бота для отправки сообщений в реальном времени
- **Процесс**: Connect() → проверка соединения → запуск горутины runBotLoop
- **Что добавить**:
  - Логирование времени запуска
  - Мониторинг состояния соединения
  - Retry logic при неудаче

#### 1.3 Остановка бота (StopBot)
- **Как работает**: POST /bots/{id}/stop - останавливает IRC клиент
- **Зачем нужен**: Остановка бота для экономии ресурсов или смены настроек
- **Что добавить**:
  - Graceful shutdown с ожиданием последнего сообщения
  - Логирование причины остановки

#### 1.4 Список ботов (ListBots)
- **Как работает**: GET /bots - возвращает массив всех ботов с статусами
- **Зачем нужен**: Просмотр всех ботов в системе
- **Что добавить**:
  - Пагинация
  - Фильтры (enabled, personality, channel)
  - Сортировка

#### 1.5 Обновление бота (UpdateBot)
- **Как работает**: PUT /bots/{id} - обновляет настройки бота
- **Зачем нужен**: Изменение параметров бота без пересоздания
- **Что добавить**:
  - Валидация при живом боте (требуется перезапуск)
  - Аудит изменений

#### 1.6 Удаление бота (DeleteBot)
- **Как работает**: DELETE /bots/{id} - удаляет бота из БД
- **Зачем нужен**: Удаление ненужного бота
- **Что добавить**:
  - Подтверждение удаления
  - Каскадное удаление логов

### 2. Message Generation (Генерация сообщений)

#### 2.1 LLM Генерация (generateMessage)
- **Как работает**: Отправляет system prompt + user prompt в LLM API, получает сгенерированное сообщение
- **Зачем нужен**: Создание уникальных контекстно-зависимых сообщений для чата
- **Личности**: весёлый_фанат, токсик, нейтрал, хайпер
- **Контекст**: Может использовать аудио-транскрипцию стрима
- **Что добавить**:
  - Поддержка кастомных промптов
  - Температура генерации
  - Repetition penalty настройки
  - Фильтрация повторяющихся сообщений

#### 2.2 Тест LLM (TestLLM)
- **Как работает**: POST /settings/test-llm - тестирует генерацию без отправки в Twitch
- **Зачем нужен**: Проверка работоспособности LLM и промптов
- **Что добавить**:
  - Выбор нескольких личностей для теста
  - Сохранение истории тестов

---

### 3. Twitch IRC Client (IRC подключение)

#### 3.1 IRC Connect
- **Как работает**: TLS подключение к irc.chat.twitch.tv:6697, аутентификация, JOIN канала
- **Зачем нужен**: Отправка сообщений в чат Twitch
- **Протокол**: IRC с TLS
- **Что добавить**:
  - Обработка rate limits от Twitch (420 error)
  - Reconnect при disconnect
  - Captcha detection

#### 3.2 SendMessage
- **Как работает**: Отправляет PRIVMSG в IRC канал
- **Зачем нужен**: Фактическая отправка сообщения в чат
- **Что добавить**:
  - Экранирование специальных символов
  - Проверка длины сообщения (макс 500 символов)

#### 3.3 Reconnect
- **Как работает**: Закрытие старого соединения, новое подключение
- **Зачем нужен**: Восстановление после потери соединения
- **Что добавить**:
  - Exponential backoff
  - Max retry limit

---

### 4. Audio Context Service (Аудио контекст)

#### 4.1 Аудио захват (captureChunk)
- **Как работает**: Использует streamlink для получения URL стрима, ffmpeg для захвата аудио
- **Зачем нужен**: Получение контекста о чем говорит стример для генерации релевантных сообщений
- **Процесс**: streamlink → resolve URL → ffmpeg capture
- **Что добавить**:
  - Поддержка нескольких аудио источников
  - Пропуск тихих сегментов
  - Шумоподавление

#### 4.2 Транскрибация (transcribe)
- **Как работает**: POST аудио в STT сервис (OpenAI Whisper совместимый)
- **Зачем нужен**: Преобразование речи в текст
- **STT**: Compatible with OpenAI Whisper API
- **Что добавить**:
  - Кеширование результатов
  - Speaker diarization
  - Punctuation restoration

#### 4.3 Контекст буфер (GetRecentContext)
- **Как работает**: Хранит последние транскрипции за TTL период
- **Зачем нужен**: Передача контекста в LLM для генерации релевантных сообщений
- **Что добавить**:
  - Векторное кеширование
  - Интеграция с memory системы

---

### 5. Channel Rotation (Ротация каналов)

#### 5.1 Ротация ботов (rotateBots)
- **Как работает**: Периодически переключает ботов на случайные каналы из списка
- **Зачем нужен**: Распределение активности между несколькими каналами
- **Интервал**: Настраиваемый (по умолчанию 60 минут)
- **Что добавить**:
  - Weighted rotation (разные каналы с разной частотой)
  - Smart rotation (избегать повторных посещений)
  - Контроль лимитов на канал

#### 5.2 Управление ротацией (startRotation/stopRotation)
- **Как работает**: Включение/выключение горутины ротации
- **Зачем нужен**: Контроль ротации через настройки
- **Что добавить**:
  - Manual trigger ротации
  - Rotation history

---

### 6. Rate Limiting

#### 6.1 Global Rate Limiter
- **Как работает**: Ограничение общего числа сообщений в минуту (по умолчанию 30)
- **Зачем нужен**: Избежатие блокировки от Twitch
- **Fallback**: Redis или in-memory
- **Что добавить**:
  - Per-channel rate limits
  - Bot-specific rate limits
  - Adaptive rate limiting

#### 6.2 Per-Bot Rate Limiting
- **Как работает**: min_delay_sec, max_delay_sec - случайная задержка между сообщениями
- **Зачем нужен**: Естественность отправки сообщений
- **Что добавить**:
  - Rate limiting по дням недели
  - Time-based variations

### 7. API Server

#### 7.1 REST Endpoints
- **Эндпоинты**:
  - GET/POST /api/bots
  - GET/PUT/DELETE /api/bots/{id}
  - POST /api/bots/{id}/start|stop
  - GET /api/stats
  - GET/POST /api/settings
  - GET /api/proxies
  - GET /api/llm/status
  - GET /api/ws (WebSocket)
- **Аутентификация**: API Key в заголовке
- **Что добавить**:
  - OpenAPI документация
  - GraphQL endpoint
  - Batch operations

#### 7.2 WebSocket Hub
- **Как работает**: Broadcast сообщений всем подключенным клиентам
- **События**:
  - bot_status_changed
  - bot_message_sent
  - stats_updated
  - audio_context
  - settings_log
- **Что добавить**:
  - Rooms/channels подписки
  - Message History API
  - Reconnection state recovery

---

### 8. Proxy Management (Управление прокси)

#### 8.1 Создание прокси (CreateProxy)
- **Как работает**: POST /proxies - сохранение прокси в БД
- **Поля**: id, host, port, username, password, protocol
- **Зачем нужен**: Использование прокси для обхода лимитов
- **Что добавить**:
  - Тестирование прокси при создании
  - Геолокация прокси
  - Типы прокси (HTTP, SOCKS5)

#### 8.2 Прокси пул (Proxy Pool)
- **Как работает**: Автоматическое переключение прокси при ошибках
- **Зачем нужен**: Отказоустойчивость при блокировке прокси
- **Что добавить**:
  - Smart proxy selection
  - Proxy rotation
  - Performance monitoring

---

### 9. Settings Management

#### 9.1 Получение настроек (GetSettings)
- **Как работает**: GET /api/settings - возвращает все настройки системы
- **Зачем нужен**: Конфигурация системы
- **Что добавить**:
  - Schema validation
  - Hot reload

#### 9.2 Сохранение настроек (UpdateSettings)
- **Как работает**: POST /api/settings - сохраняет и применяет настройки
- **Изменения**: channels, LLM, audio, rotation, debug
- **Что добавить**:
  - History изменений
  - Rollback
  - Import/Export

---

### 10. Logging & Analytics

#### 10.1 Bot Logs
- **Как работает**: Логирование всех действий ботов в PostgreSQL + Redis
- **Типы**: lifecycle, message, error, rate_limit, llm
- **Что добавить**:
  - Log levels (debug, info, warn, error)
  - Log aggregation
  - Alerting

#### 10.2 Stats
- **Как работает**: GET /api/stats - общее количество ботов и запущенных
- **Зачем нужен**: Мониторинг системы
- **Что добавить**:
  - Messages per minute/hour
  - Uptime tracking
  - Error rates

---

### 11. Security

#### 11.1 Аутентификация
- **Как работает**: API Key в заголовке X-API-Key
- **Зачем нужен**: Защита API от несанкционированного доступа
- **Что добавить**:
  - JWT токены
  - OAuth2 провайдеры
  - Two-factor authentication

#### 11.2 Rate Limiting API
- **Как работает**: 100 запросов в минуту на клиента
- **Зачем нужен**: Защита API от злоупотреблений
- **Что добавить**:
  - Per-endpoint limits
  - IP blacklisting

## Базы данных

### Таблицы PostgreSQL

1. **bots** - Конфигурации ботов
2. **bot_logs** - Логи ботов
3. **settings** - Глобальные настройки
4. **settings_logs** - Логи изменений настроек
5. **proxies** - Список прокси

### Redis Keys

1. `global_rate_limit` - Счетчик глобальных сообщений
2. `bot:{id}:messages` - Последние сообщения бота
3. `bot:{id}:stats` - Статистика бота

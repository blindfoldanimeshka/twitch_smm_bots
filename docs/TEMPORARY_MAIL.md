# Временная почта

## Основное: in-app Guerrilla inbox

Временная почта встроена в приложение: Go-бэкенд работает с публичным API
Guerrilla Mail (`internal/guerrilla` — клиент, `internal/tempmail` — сервис),
ящик создаётся и читается прямо из Settings. **Не нужно: аккаунт, свой домен,
Cloudflare Email Routing, Worker или отдельный контейнер.**

Маршруты (все под существующим `X-API-Key`):

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/temp-mail/inbox` | создать ящик (опционально alias) |
| GET | `/api/temp-mail/inbox/{id}` | ящик + список писем |
| GET | `/api/temp-mail/inbox/{id}/messages/{mailID}` | текст письма |
| DELETE | `/api/temp-mail/inbox/{id}` | удалить ящик |

Как это работает:

- Сервис создаёт ящик у Guerrilla и хранит сессию (`sid_token`) **только на
  бэкенде** в Redis под ключом `tempmail:<id>` с TTL **1 час**. Наружу отдаётся
  только наш `id` ящика — `sid_token` не покидает бэкенд, не возвращается в
  ответах и не логируется.
- Ящик живёт 1 час: Guerrilla сам удаляет письма через час, Redis-сессия
  живёт столько же. Истёкший `id` даёт 404.
- Тело письма — чужой HTML. Бэкенд вырезает теги (включая `script`/`style`) и
  отдаёт только текст; фронтенд рендерит его как текст, никогда как HTML.
- Сбой Guerrilla (429/5xx/таймаут) отдаётся как 502 с понятным текстом.

### Ограничения — примите до использования

- **Receive-only**: отправлять письма с этого адреса нельзя, только принимать.
- **Домены общие** (`guerrillamail.com` и т.п.): многие сервисы их блокируют —
  письмо от такого сервиса может просто не дойти.
- **Ящик публичный**: Guerrilla (и любой, кто знает адрес) видит содержимое
  писем. Не принимайте на него пароли, токены и что-либо конфиденциальное.
- **Это сторонний бесплатный сервис без SLA**: может деградировать,
  лимитировать запросы или исчезнуть в любой момент.

## Не для обхода верификации

> **Не используйте временную почту для обхода верификации сторонних платформ**
> (Twitch и любых других — это прямое нарушение их правил).

Inbox предназначен **только для собственных тестовых писем** проекта: проверка
собственных рассылок, регистрационных писем нашего стенда, e2e-тестов потока
«письмо → ссылка/код».

## Опционально: TempFastMail (self-hosted)

Запасной вариант для тех, кому нужен изолированный self-hosted сервис с
собственным UI и админкой. Контейнер `tempfastmail` в `docker-compose.yml`
выведен в **профиль `mail`** — обычный `docker compose up` его **не запускает**.

- Исходный код и образ: <https://github.com/kasteckis/TempFastMail> (лицензия **GPL-3.0**).
- Мы запускаем **опубликованный образ `kasteckis/tempfastmail:1.0.0` без изменений**
  (версия закреплена: миграции SQLite/stateful — `:latest` не используем)
  и не копируем его код в этот репозиторий.
- Хранилище — SQLite в named-томе `tempfastmail_data` (`/app/sqlite` в контейнере).
- Письма и ящики автоматически удаляются через `DELETE_EMAILS_AND_INBOXES_OLDER_THAN_HOURS`
  (по умолчанию **48 часов**).

Фронтенд с TempFastMail не связан: карточка в Settings работает только с
Guerrilla inbox. У TempFastMail свой собственный веб-UI.

### Важно: сервис сам НЕ принимает SMTP-почту

TempFastMail не слушает 25-порт и не является почтовым сервером. Чтобы письма
действительно доходили до инстанса, нужна цепочка доставки через Cloudflare:

1. Домен на Cloudflare, включённый **Email Routing** с catch-all правилом
   (все письма на домене пересылаются в Worker).
2. Cloudflare Worker **`kasteckis/cloudflare-email-worker-html-parser`**, который
   публикует полученные письма в наш инстанс по HTTP API.
3. Worker авторизуется значением `CREATE_RECEIVED_EMAIL_API_AUTHORIZATION_KEY`
   (наш `.env` — `TEMPFASTMAIL_API_KEY`).

Полная инструкция по настройке:
<https://github.com/kasteckis/tempfastmail/blob/master/docs/CLOUDFLARE_EMAIL_WORKER_SETUP.md>

### Сетевой доступ

По умолчанию контейнер биндится только на loopback:

```yaml
ports:
  - "${TEMPFASTMAIL_BIND:-127.0.0.1}:${TEMPFASTMAIL_PORT:-8090}:80"
```

То есть сервис доступен лишь как `http://localhost:8090` на хосте. Для приёма
реальных входящих писем (Worker должен достучаться до инстанса из интернета)
выставляйте его **только через Cloudflare Tunnel или TLS-обратный прокси**
(nginx/caddy с HTTPS). **Не открывайте 80-й порт хоста напрямую.**

### Первая настройка

- Учётная запись администратора по умолчанию: `admin@admin.dev` / `admin`.
  **Смените пароль сразу после первого входа.**
- Переменные (`docker-compose.yml` → `.env`, см. `.env.example`):
  - `TEMPFASTMAIL_APP_SECRET` — сгенерировать: `openssl rand -hex 32`, не коммитить.
  - `TEMPFASTMAIL_API_KEY` — общий секрет с Cloudflare Worker (в настройках Worker).
  - `TEMPFASTMAIL_URI` — публичный URL сервиса.
  - `TEMPFASTMAIL_RETENTION_HOURS` — срок хранения писем.
  - `TEMPFASTMAIL_BIND` / `TEMPFASTMAIL_PORT` — привязка на хосте.

### Безопасность

- Держите `TEMPFASTMAIL_API_KEY` в секрете: кто знает ключ, тот может писать
  письма в любой ящик через API. Не светите его в логах и фронтенде.
- Задайте сильный `APP_SECRET` (иначе сессии и CSRF-защита Symfony предсказуемы).
- **Не выставляйте админ-UI в интернет без дополнительной авторизации**
  (tunnel с access-policy, basic-auth прокси или хотя бы смена пароля админа
  и закрытая регистрация).
- Ограничьте ретеншен (`TEMPFASTMAIL_RETENTION_HOURS`) — не храните письма
  дольше, чем нужно; в БД не должно быть никаких секретов.
- Реальные секреты не коммитить: `.env` вне git, в `.env.example` только пустые
  значения/заглушки.

### Команды

```bash
# запустить (профиль mail обязателен)
docker compose --profile mail up -d tempfastmail

# логи
docker compose --profile mail logs -f tempfastmail

# UI (свой, вне нашего фронтенда)
http://localhost:8090
```
